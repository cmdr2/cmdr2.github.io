C pointers vs Rust references:

| C | Rust | Can Change Value? | Can Change Pointer? (To something else) |
| :--- | :--- | :--- | :--- |
| `const int *const ptr` | `let ptr: &i32` | ❌ No | ❌ No |
| `const int *ptr` | `let mut ptr: &i32` | ❌ No | 🟢 Yes |
| `int *const ptr` | `let ptr: &mut i32` | 🟢 Yes | ❌ No |
| `int *ptr` | `let mut ptr: &mut i32` | 🟢 Yes | 🟢 Yes |


These govern whether the pointer reference allows modifications to the referenced value, and whether the pointer itself can be modified to point to something else.

A key addition in Rust is compile-time book-keeping of references:
* only one mutable reference to a value at a time
* can't have a mutable and immutable reference at the same time
* can have multiple immutable references at the same time

C will allow all of these, and is mutable by default whereas Rust is immutable by default.
